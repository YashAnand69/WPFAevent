# Fork-only WordPress navigation validation

This directory and `.github/workflows/validate-navigation.yml` are validation-only. They must not enter the upstream contribution diff. The workflow is limited to pushes on `validation/navigation-nov1` in `YashAnand69/WPFAevent`, with `contents: read`, checkout credentials disabled, and no access to production secrets or deployment services. It uses a disposable MySQL service with explicitly fake local credentials. It never writes to a remote source branch.

Before pushing, replace `SOURCE_SHA` with the parent-approved exact contribution commit. `BASE_SHA` is af771bf3291366bea2b70ab636f15aea073d01f6. The source commit must be a descendant of that base and already present in the fork. No moving source branch or unreviewed downloaded fix is used. The validation branch itself supplies the harness; source is checked out separately under `plugin`.

The job requires PHP 8.2, MySQL 8, repository Composer dependencies, Node 24, locked repository npm dependencies, and pinned Playwright 1.64.1/Chromium. The latter version was obtained from the official microsoft/playwright latest release. Browser dependencies are isolated from the contribution's manifests and lockfiles.

## Gates

1. `phpcbf` is limited to the new `EventHeaderNavigationTest.php`. Any resulting format patch is uploaded, and the format gate fails until that patch has been reviewed/applied on the contribution branch and a new exact SHA validated. No existing source file is autoformatted.
2. Candidate PHPUnit tests run while only the four production files are swapped to the baseline. The baseline must fail with actual PHPUnit assertions, not import/setup errors. A trap restores source from the exact contribution commit.
3. Full repository PHPUnit, PHPCS, PHPStan, npm lint and `test:navigation` run. Every gate is mandatory; `continue-on-error` only allows all logs/artifacts to be collected. The final step fails if any gate failed/skipped.
4. WP-CLI installs an actual independent WordPress site/database and activates the actual plugin. A seed creates only placeholder event data and real metadata/templates, not fabricated HTML. The PHP built-in server is loopback-only with opcode caching disabled. Pretty URLs use a small conventional front-controller router.
5. Actual classic Twenty Twenty-One and block Twenty Twenty-Three themes are installed/activated. Each is exercised before/after under 1440x1000 and 390x844 viewports. Global/event/custom-page screenshots are taken. Both event/custom header assertions must fail on baseline in each viewport while the global controls pass; missing-target/import/HTTP/JavaScript failures are not accepted as successful reproductions.
6. On fixed source, actual Chromium scrolling/focus/history and navigation are checked: fallback smooth, Enter keyboard activation, reduced-motion instant, native CSS smooth, native control-click and named-target tabs, and real event → custom-page → parent-anchor routes. `scrollIntoView` is observed but calls through to the native method; no fake targets, scrolling implementation or navigation assignment is substituted. Native CSS smooth uses explicitly controlled stylesheet overrides; it is not claimed as stock theme CSS.
7. Real WordPress `esc_url`, `esc_url_raw` and registered navigation metadata sanitization are recorded for malformed HTTP hosts. Stored candidates render in the actual secondary navigation, then native clicks execute the actual production handler on baseline/fixed. Uncaught errors fail validation. An omitted or sanitized candidate is recorded as unreproduced, never fabricated as a bug. The original metadata is restored after the probe.

WordPress/core/theme versions, exact source SHA, raw check logs, page exceptions, console errors, failed local resources, intentionally blocked external resources, URLs, actual screenshots and JSON assertions are retained. External network resources are blocked to prevent third-party dependency or outbound event operations; that limitation must be reported, not described as complete connected-service testing. No live Eventyay API, real attendee data, Safari/Firefox, deployed site, production database or human manual QA is exercised. The full PHP requirement remains binding even if a failure also exists on baseline; compare logs before attributing it to the patch.

Only syntax/static harness checks have run locally until a fork workflow run is completed. A passing local Node/bash syntax check is not PHP, WordPress or browser validation.
